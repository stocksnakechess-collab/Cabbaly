# CABBALY

Мобильная социальная сеть (PWA), интерфейс на русском. Next.js + TypeScript + Tailwind + Supabase.

## Что проверено, а что нет

| Что | Статус |
|---|---|
| Юнит-тесты проверок (`npm test`): имя, пароль, дата рождения, вопрос о создателе, пути к фото, лимит запросов | ✅ запускались, 9 из 9 проходят |
| Все импорты и ссылки на файлы, иконки, манифест PWA, цвета Tailwind | ✅ проверены скриптом |
| Типы TypeScript в собственном коде проекта | ✅ проверены с заглушками для Next/React/Supabase |
| Файлы настроек (`next.config.mjs`, `package.json`, `tsconfig.json`) | ✅ загружаются без ошибок |
| `npm install`, `npm run build`, `npm run dev` | ❌ **ни разу не запускались** (в среде разработки нет интернета) |
| Типы самих библиотек Next/React/Supabase | ❌ не проверены — это сделает `npm run build` у вас |
| Вход, регистрация, лента, посты, фото, лайки, комментарии, подписки, поиск, уведомления | ❌ **код написан, но не запускался** (нужны реальный Supabase и запуск) |
| Установка на телефон как приложение (PWA) | ❌ не проверялась; нужен адрес HTTPS (в Codespaces он есть, но это не проверено) |
| Заявки на верификацию, панель владельца, восстановление пароля, CAPTCHA | ❌ не сделано |

Поэтому первый запуск может показать ошибки. Это нормально: скопируйте текст ошибки и пришлите мне.

## Что вам понадобится
- Телефон Android с браузером Chrome и электронная почта.
- Бесплатные аккаунты на **GitHub** и **Supabase**.
- Ничего устанавливать на телефон не нужно: проект запускается в облачном редакторе **GitHub Codespaces** прямо в браузере.
  Бесплатно в месяц: 120 «ядро-часов», то есть около 60 часов работы на малой машине. Лишнее время не списывается без вашей карты.

> Я не мог проверить эти шаги на реальном телефоне. Названия кнопок могут немного отличаться — если что-то не совпадает, пришлите скриншот.
> Если страница GitHub выглядит тесно, в Chrome нажмите ⋮ → поставьте галочку **«Версия для ПК»**.

## Часть 1. Облачный редактор (GitHub)

1. Откройте https://github.com и нажмите **Sign up**. Создайте аккаунт и подтвердите почту.
2. Откройте https://github.com/new. В поле **Repository name** напишите `cabbaly`. Выберите **Private**. Поставьте галочку **Add a README file**. Нажмите **Create repository**.
3. На странице репозитория нажмите зелёную кнопку **Code** → вкладка **Codespaces** → **Create codespace on main**. Подождите 1–2 минуты, откроется редактор.
4. Загрузите архив проекта: в левой панели **Explorer** нажмите на пустое место и удерживайте (или нажмите «⋯» → **Upload…**), выберите `cabbaly.zip` из «Загрузок».
5. Откройте терминал: кнопка меню ☰ (слева сверху) → **Terminal** → **New Terminal**. Введите по очереди (каждая строка — Enter):
   ```
   unzip cabbaly.zip
   cp -r cabbaly/. .
   rm -rf cabbaly cabbaly.zip
   npm install
   ```
   Если на первой строке ошибка `unzip: command not found`, выполните `sudo apt-get update && sudo apt-get install -y unzip` и повторите.
   `npm install` занимает несколько минут. Строки `warn` — не страшно. Если есть строки с `ERR!` — пришлите их мне.
6. Проверка сборки (очень полезна, пришлите мне результат):
   ```
   npm test
   npm run build
   ```
   В конце `npm run build` должно быть «Compiled successfully» и список страниц. Если вместо этого ошибка — скопируйте её целиком.

## Часть 2. Supabase (база данных)

Откройте новую вкладку Chrome (редактор оставьте открытым).

1. Зайдите на https://supabase.com → **Start your project**, войдите через GitHub.
2. **New project**: название `cabbaly`, придумайте и сохраните пароль базы, регион — ближайший. Подождите 1–2 минуты.
3. **Создание таблиц.** Вернитесь во вкладку с редактором, откройте файл `supabase/migrations/0001_init.sql` (в Explorer), нажмите на текст, затем удерживайте палец → **Select All** → **Copy**. Во вкладке Supabase: меню **SQL Editor** → **New query** → вставьте текст → **Run**. Должно появиться «Success. No rows returned». Если ошибка — пришлите её мне.
4. Меню **Storage**: убедитесь, что есть два хранилища, `avatars` и `post-images`.
5. Меню **Authentication → Sign In / Providers**: найдите переключатель **Allow new users to sign up** и **выключите** его. Сохраните. (Аккаунты создаёт наш сервер с проверками; прямую регистрацию через Supabase надо закрыть.)
6. Нужные значения:
   - **Project URL** — нажмите кнопку **Connect** сверху или откройте **Project Settings → API**; адрес вида `https://xxxx.supabase.co`.
   - **Publishable key** (начинается с `sb_publishable_`) и **Secret key** (начинается с `sb_secret_`) — **Project Settings → API Keys**. Если ключей нет, нажмите **Create new API Keys**. В старых проектах это ключи `anon` и `service_role` — тоже подходят.

   ⚠️ **Secret key — секрет.** Никому его не показывайте и не отправляйте в чат.

## Часть 3. Настройки и запуск

1. В терминале редактора: `cp .env.example .env.local`
2. В Explorer откройте файл `.env.local` и впишите значения после знака `=` (без кавычек и пробелов):
   - `NEXT_PUBLIC_SUPABASE_URL` — Project URL
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` — Publishable key
   - `SUPABASE_SERVICE_ROLE_KEY` — Secret key
   - `OWNER_SETUP_TOKEN` — случайная строка. Получить: в терминале `node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"`, скопировать результат.
3. Запуск: `npm run dev`
4. Внизу появится окошко «Your application running on port 3000 is available» → **Open in Browser**. Если окошка нет: вкладка **Ports** (внизу) → строка 3000 → значок глобуса. Откроется адрес вида `https://…-3000.app.github.dev`. Это и есть CABBALY. Сохраните его в закладки Chrome.
5. Если вместо входа вы видите «Нужна настройка» — проверьте `.env.local`, остановите сервер (Ctrl+C или закройте терминал) и запустите `npm run dev` снова.

> Редактор усыпляется после нескольких минут без активности — тогда сайт перестанет открываться. Снова откройте https://github.com/codespaces, запустите ваш codespace и введите `npm run dev`.
> Когда закончите, удалите ненужные codespace на https://github.com/codespaces — они расходуют бесплатные часы и место.

## Часть 4. Аккаунт владельца
Откройте `<ваш адрес>/owner-setup` (не входя в аккаунт). Введите имя, фамилию, пароль и код из `OWNER_SETUP_TOKEN`. Будет создан аккаунт `cabbaly`. Работает один раз; это имя нельзя занять обычной регистрацией. Если имя уже занято другим аккаунтом, права **не выдаются** — вы увидите объяснение.

## Часть 5. Проверка функций (с двумя пользователями)
Откройте сайт в Chrome и в режиме инкогнито — это два пользователя, A и B.
1. **Регистрация A:** «Создать аккаунт». Проверьте кнопку «Проверить», неверный ответ на вопрос о создателе (ошибка), разные пароли (ошибка). Затем успешная регистрация → аватар или «Пропустить» → лента.
2. **Выход и вход:** Настройки → «Выйти из аккаунта» → войдите снова. Неверный пароль → общая ошибка.
3. **Пост A:** кнопка «+» → текст и 1–4 фото → «Опубликовать». Обновите страницу — пост на месте.
4. **Пост B:** у A должна появиться плашка «Есть новые публикации. Обновить» (или пост виден после обновления).
5. **Лайк:** B ставит и убирает лайк; у A появляется и исчезает уведомление.
6. **Комментарий:** B комментирует пост A; A может удалить любой комментарий под своим постом, B — только свои.
7. **Подписка:** B открывает профиль A → «Подписаться»; у A — уведомление, вкладка «Подписки» у B показывает посты A.
8. **Поиск:** найдите A по имени, фамилии, части имени пользователя.
9. **Правка:** A меняет текст поста (карандаш) и удаляет пост (корзина).
10. **Настройки:** смена имени, описания, имени пользователя (затем вход с новым), аватара, пароля.
11. **Защита:** у B нет кнопок правки чужих постов; открыть чужой `/post/<id>/edit` нельзя.

Чтобы увидеть значок подтверждения до появления панели владельца: Supabase → **Table Editor** → таблица `profiles` → у нужной строки поставьте `is_verified = true`.

## Если что-то не работает
| Симптом | Что делать |
|---|---|
| `Invalid Server Actions request` или кнопки «Войти»/«Опубликовать» ничего не делают | Откройте сайт именно по адресу `…app.github.dev` из вкладки Ports; пришлите текст ошибки из терминала |
| Регистрация: «Что-то пошло не так» | В терминале найдите строку `[createAccount]` — в ней причина. Если Supabase называет адрес некорректным, добавьте в `.env.local` строку `INTERNAL_EMAIL_DOMAIN=` и домен, которым владеете, и перезапустите |
| `Нужна настройка` | Не заполнен `.env.local` или сервер не перезапущен |
| Не загружается фото | Проверьте, что в Supabase → Storage есть `avatars` и `post-images` (шаг SQL выполнен); файл JPEG/PNG/WebP, аватар до 2 МБ, фото до 5 МБ |
| Сайт перестал открываться | Codespace уснул — запустите его снова и выполните `npm run dev` |

## Если у вас есть компьютер
Вместо Частей 1 и 3 можно запустить локально: установите Node.js LTS (https://nodejs.org), распакуйте архив, в папке выполните `npm install` и `npm run dev`, откройте http://localhost:3000. Остальное — как выше.

## Как это устроено
- Вход по **имени пользователя**. Supabase Auth требует e-mail, поэтому каждому аккаунту присваивается внутренний адрес `<имя>@users.cabbaly.invalid`. Письма туда не уходят.
- Регистрацию выполняет **сервер**: он проверяет данные и ответ на вопрос о создателе, ограничивает частоту попыток и создаёт аккаунт. Пароль хранит и хеширует Supabase Auth. Секретный ключ не попадает в браузер.
- Права обеспечивает **база данных** (RLS и права на колонки): пользователь меняет только свои профиль, посты, лайки и комментарии; `is_verified`, `is_suspended`, `username` и роли ему недоступны. Уведомления создаются триггерами.
- Фото загружаются из браузера в Supabase Storage в папку пользователя; хранилище ограничивает тип (JPEG/PNG/WebP) и размер; сервер дополнительно проверяет пути.

## Ограничения (до запуска для людей)
- **Восстановление пароля не реализовано** (у аккаунтов нет настоящей почты). Варианты: необязательный e-mail или сброс пароля владельцем.
- **Нет CAPTCHA.** Вопрос о создателе — не защита от ботов. Лимит запросов хранится в памяти процесса и не подходит для нескольких серверов.
- Фото доступны по прямой ссылке (имена случайные, но это не приватность); тип файла проверяется только по заявленному типу и ограничениям хранилища.
- Фото в опубликованном посте изменить нельзя (можно удалить пост); при обрыве загрузки в хранилище может остаться лишний файл.
- Поиск — простое совпадение по подстроке; для большой базы нужен индекс. Нет списков подписчиков (только счётчики), жалоб и модерации.
- Страница `/design` доступна только в режиме разработки.

```
src/lib/            проверки, клиенты Supabase, запросы ленты, ограничение частоты
src/messages/ru.ts  все тексты интерфейса
src/middleware.ts   защита страниц и обновление сессии
supabase/migrations схема базы данных и политики безопасности
tests/              юнит-тесты
```
